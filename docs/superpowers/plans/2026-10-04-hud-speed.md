# HUD Speed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut wasted agent steps in HUD tasks (measured: a 142s, 51-call task) by carrying prior-task context into new hotkey sessions, removing the forced `SKILL.md` read, telling the agent which macOS paths are blocked, and silencing per-call node warnings.

**Architecture:** All changes are in `packages/daemon/src`. `HudCoordinator` remembers a short digest (goal + summary) of the last finished task and injects it into the next task prompt when a new hotkey session starts within 10 minutes. Two prompt strings (`formatContextualTaskPrompt` rule 4, `SLIM_COMPUTER_PROMPT` rule 3) are edited in place without renumbering. `WarmAgySession` and `ProcessAgentRunner` set `NODE_NO_WARNINGS=1` in the agent's environment so every `rh` subprocess skips the SQLite warning.

**Tech Stack:** TypeScript, vitest (`npm test` from the repo root runs `vitest run`), pnpm workspace.

**Spec:** None written. The evidence and diagnosis are the HUD task log review in this session (`~/.remote-hands/local.db`, tasks `a7ec9d3f` survey 72s and `3a95add7` notes+Spotify 142s, 2026-10-04). Measured waste in task `3a95add7`: ~28s reading the previous task's transcript in `~/.gemini/antigravity-cli/brain/`, ~35s on blocked osascript paths, ~6s reading the 285-line `SKILL.md`.

## Global Constraints

- Do not renumber the rules in `SLIM_COMPUTER_PROMPT` or the `formatContextualTaskPrompt` execution mandate. Existing tests locate rules with `startsWith('3.')`, `startsWith('5. ')`, `startsWith('8.')`.
- `SLIM_COMPUTER_PROMPT` must mention exactly the tool names `buildComputerTools` produces (test in `computer/prompt.test.ts`). Do not write any `desktop_*` or `browser_*` word that is not a real tool name.
- Rule 3 of `SLIM_COMPUTER_PROMPT` must keep the text `except the physical-click fallback that desktop_click reports in its result`.
- Existing test `preserves conversation_id across follow-up prompts in the same HUD session` must keep passing: same-session follow-ups keep using `conversation_id`, and get no digest.
- Digest window is exactly `10 * 60_000` ms. Digest summary is capped at exactly 2000 characters.
- Commit messages follow the repo style: `fix(hud): ...`.

## Review Focus

- Summary is empty or whitespace: the digest must be skipped, not injected as an empty section.
- Summary longer than 2000 chars: truncated with a visible marker, never dropped.
- Previous task failed or was cancelled: no digest (only a successful `completeTask` records one).
- Digest older than 10 minutes: not injected.
- A follow-up in the same hotkey session (`currentConversationId` set): no digest, because the conversation already holds the history.

In `hud-coordinator.ts`, directly above `export function formatContextualTaskPrompt(`, add:

```ts
export interface PreviousTaskDigest {
  goal: string;
  summary: string;
  finishedAt: number;
}

export const PREVIOUS_TASK_WINDOW_MS = 10 * 60_000;
export const PREVIOUS_TASK_SUMMARY_MAX = 2000;

export function formatPreviousTaskSection(prev: PreviousTaskDigest | undefined, nowMs: number): string[] {
  if (!prev) return [];
  const summary = prev.summary.trim();
  if (!summary) return [];
  if (nowMs - prev.finishedAt > PREVIOUS_TASK_WINDOW_MS) return [];
  const body =
    summary.length > PREVIOUS_TASK_SUMMARY_MAX
      ? `${summary.slice(0, PREVIOUS_TASK_SUMMARY_MAX)}\n[summary truncated]`
      : summary;
  return [
    '',
    'Previous task (just finished). Use this as ground truth for follow-up requests such as "add those answers to a note"; do not re-derive it from transcripts or files:',
    `Goal: ${prev.goal}`,
    'Result:',
    body,
  ];
}
```
