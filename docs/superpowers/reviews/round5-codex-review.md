### [P2] Hidden boxless wrappers now discard visible descendants

`packages/daemon/src/browser/page-scripts.ts:469`, `packages/daemon/src/browser/page-scripts.ts:505`

Scenario: `<main><div style="display:contents;visibility:hidden"><span style="visibility:visible">Visible invoice</span></div></main>`. The span renders: descendants can override inherited visibility, as specified by [CSS Display 3](https://www.w3.org/TR/css-display-3/#visibility). The changed exemption makes `hidden(wrapper)` true, and `walk` returns before visiting the visible span. A fresh exported-script comparison returned `Visible invoice` on `40eb8f1^` and an empty string on `40eb8f1`. The same failure occurs with a boxless open shadow host whose shadow child overrides visibility. This affects fast extraction and the legacy driver's shared extraction script. The experiment uses real DOM traversal and computed visibility, with the missing jsdom `checkVisibility` primitive modeled as false for the boxless wrapper.

Suggested fix: distinguish pruning an entire subtree from suppressing a node's own text. Traverse boxless wrappers with hidden visibility, suppress their hidden direct text, and evaluate each child's effective visibility. Pin both hidden direct text and visible descendant overrides, including shadow children. The new test at `page-scripts.test.ts:1555` covers only direct text and passes despite this regression.

### [P2] Memoizing frame transforms introduces a stack-depth failure

`packages/daemon/src/browser-snapshot.ts:144`

Scenario: a visible, untransformed same-origin iframe under 15,000 programmatically constructed ordinary div ancestors. This is below the 100,000-element discovery budget; the frame/shadow nesting limit does not limit ordinary DOM ancestry. `transformed` now recursively calls itself once per ancestor. A fresh actual-DOM fixture had 15,003 ancestors including the frame/body/html: the predecessor exported snapshot listed `Pay`, while the current snapshot returned `{"error":"snapshot failed: Maximum call stack size exceeded"}`. The whole snapshot fails, rather than merely omitting the frame. A separate modeled ancestor chain reproduced the same predecessor/current difference.

Suggested fix: retain an iterative ancestor walk, stop at a memoized result, and populate the memo for the traversed chain afterward. Pin a deep chain as well as shared-ancestor work counts. This experiment models computed styles and frame geometry; jsdom's recursive construction notifications were disabled only while building the fixture, then restored before executing either snapshot. No snapshot ancestor links were replaced in the actual-DOM fixture. Native browser rendering was unavailable, so the exact depth threshold is not a browser-specific claim.
