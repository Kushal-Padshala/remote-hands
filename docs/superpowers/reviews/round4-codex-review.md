### [P2] Identity scale and rotation make ordinary frames unreadable

`packages/daemon/src/browser-snapshot.ts:132`

Scenario: an otherwise untransformed, visible 200×200 same-origin iframe sits inside `<div style="scale:1">` or `<div style="rotate:0deg">`. These are identity transforms, but the new ancestor check rejects every non-`none` individual scale/rotate value. The frame's controls disappear and `frames_blocked` becomes 1, even though adding offsets remains valid. A fresh actual-snapshot experiment with the corresponding computed-style values listed `Pay` using the parent commit's script and omitted it using the current script. This is a new regression. The current transform test always supplies `rotate:'none', scale:'none'`, so it cannot protect this case. The distinction between `none` and identity individual transforms is defined in [CSS Transforms 2](https://drafts.csswg.org/css-transforms-2/#individual-transforms).

Suggested fix: determine whether the effective individual transforms change the coordinate mapping; accept identity scale and rotation as well as translation. Test identity values on an ancestor and shadow host, alongside genuinely transformed ancestors. The experiment models computed styles and geometry; it is not a native rendering run.

### [P2] An earlier capture handler makes the new-tab hint inspect a nested click

`packages/daemon/src/browser/page-scripts.ts:263`, `docs/development.md:162`

Scenario: a page's existing window capture listener handles the Docs `_blank` link by synchronously calling another button's `.click()`. That nested dispatch reaches the injected recorder before the outer link dispatch does. Keeping the first event therefore keeps the button event. If the button cancels its click and the link proceeds normally, the current script drops `opened`; the parent commit correctly returned `opened:true`. Conversely, when that capture handler cancels the link and the button does not cancel, the current script returns `opened:true`; the parent correctly suppressed it. Both directions were reproduced with actual event dispatch and exported action scripts. The new target-level nested-click test exercises the opposite dispatch order and passes despite this regression. The guide's cancellation qualification is false for this fixture.

Suggested fix: capture the activation event belonging to the intended element, using its composed path to handle shadow retargeting, rather than the first arbitrary click. Preserve the uncertainty behavior when that event cannot be observed. Pin reentrancy from an already-registered window capture handler in both cancellation directions.

### [P2] The display:contents exemption includes CSS-invisible direct text

`packages/daemon/src/browser/page-scripts.ts:462`

Scenario: `<main><div style="display:contents;visibility:hidden">Invisible invoice</div></main>`, or a similarly styled open shadow host containing that text directly. `checkVisibility()` returns false because the wrapper has no box. The new exemption ignores that false result whenever display is `contents`, and direct Text nodes then bypass further visibility checks. Fresh extraction returned `Invisible invoice`; the parent script returned an empty string. This affects both fast extraction and the legacy driver, which shares the script. The new extraction test supplies a visible boxless wrapper, so it passes with this regression.

Suggested fix: distinguish missing boxes from actual flat-tree hiding, and test the visibility context of direct text before adding it. Keep traversing boxless wrappers while excluding text whose inherited visibility is hidden. Pin both the visible and CSS-hidden boxless cases. The native no-box result is specified by [CSSOM View](https://drafts.csswg.org/cssom-view/#dom-element-checkvisibility); this experiment stubs that primitive because jsdom lacks it.
