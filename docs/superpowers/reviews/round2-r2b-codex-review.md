### [P0] Label guidance promises current-page uniqueness but resolves against an old page

`packages/daemon/src/computer/tools.ts:176`, `docs/development.md:158`, `packages/cli/src/system/operator-skill.ts:67`, `.agents/skills/remote-hands-operator/SKILL.md:63`; implementation: `packages/daemon/src/browser/engine.ts:883`, `packages/daemon/src/browser/page-scripts.ts:219`.

Scenario: snapshot a page with one account panel's Save button. Before the next call, an asynchronous update inserts a second panel with another Save button. Call `browser_do([{op:"click",target:"Save"}])`. The actual engine resolves the label using `shown.state`, not the controls visible now. Its action guard checks the old node's identity, label and visibility, not current uniqueness. The throwaway engine experiment clicked the first panel (`wrong: 1`, `intended: 0`) without an ambiguity error; only the resulting delta disclosed the second Save. The new/revised guidance explicitly promises current visible-control matching and ambiguity failure, and the operator guidance encourages label use. The cap fix does not cover this case.

Suggested fix: prove label uniqueness against a fresh, bounded candidate set in the pinned document immediately before executing each label-targeted operation, preserving the document guard and failing closed on incomplete traversal. Until implemented, describe resolution as using the last snapshot and remove the current-page safety promise. Test duplicate insertion after a snapshot and during an earlier batch step.

### [P2] A partial append permanently breaks the call log's JSONL format

`packages/daemon/src/computer/call-log.ts:38`, `packages/daemon/src/computer/call-log.test.ts:34`, `docs/development.md:162`.

Scenario: disk space runs out after an append writes part of a record. `appendFileSync` can leave that prefix behind before throwing. The catch preserves the tool result, but the next successful record is appended directly to the unfinished line. A fault-injection experiment wrote 13 bytes then threw ENOSPC; the original record survived, but the next record became `{"at":"partia{"at":"after",...}` and was no longer separately readable. The documented `jq -s` command cannot parse this log. Renaming fixes destructive trimming, not this newly untested append failure. The rotation test seeds a healthy file and never injects a partial append.

Suggested fix: handle unfinished tails under a coordination scheme that cannot truncate another process's append, or use separately coordinated per-process logs. Add partial-write/ENOSPC followed by recovery tests that parse every retained line and verify the following record remains readable.

### [P2] Frame clipping uses the border box as the child viewport

`packages/daemon/src/browser-snapshot.ts:148`, `packages/daemon/src/browser-snapshot.ts:155`, `docs/development.md:156`, `packages/daemon/src/computer/tools.ts:176`.

Scenario: an iframe has a 100×100 content viewport and 50 px borders, making its outer rectangle 200×200. A child button lies at child x=110..130, outside that viewport. The revised clipping code offsets by the border but clips against the outer rectangle, so the button's translated center is accepted inside the border area. A geometry-controlled experiment with `window.CSS` present returned `Offscreen inside frame`. The previous code also checked the child's own viewport; that check was removed. Scaling/rotation additionally cannot be represented by simply adding child coordinates to the transformed frame rectangle. This contradicts the new visible-on-screen guarantee.

Suggested fix: intersect the child's actual content viewport at each frame boundary, and map child coordinates through transforms or fail closed for unsupported transforms. Test borders and transforms with real layout. Existing jsdom clipping tests leave `window.CSS` undefined, bypassing the action geometry rejection, and their zero-border mocks do not pin this case.

### [P2] Cancelled links still produce the new-tab hint when propagation stops

`packages/daemon/src/browser/page-scripts.ts:236`, `docs/development.md:160`.

The new documentation's cancellation qualification and the related disposition do not hold for this ordinary event pattern.

Suggested fix: retain the actual dispatched click event and inspect its `defaultPrevented` after dispatch, rather than relying on a window bubble observer. Pin cancellation with stopped propagation, including a shadow-root link.
